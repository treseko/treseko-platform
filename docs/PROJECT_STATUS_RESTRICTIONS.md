# Estados de proyecto

El estado ayuda a comunicar en qué etapa se encuentra un proyecto. Elegilo
desde la configuración del proyecto para que el equipo sepa si puede seguir
planificando, ejecutando o solo consultando información.

| Estado | Cuándo usarlo |
|---|---|
| Planificación | El proyecto se está preparando y todavía no entra en operación QA. |
| Activo | El equipo trabaja normalmente sobre casos, builds y ejecuciones. |
| En QA | El foco está en validar una build o entrega. |
| Bloqueado | Existe un impedimento que requiere atención antes de continuar. |
| Mantenimiento | Se realizan tareas controladas y se evita la operación habitual. |
| En pausa | El trabajo queda temporalmente detenido. |
| Cerrado | El proyecto finalizó y se conserva para consulta. |
| Archivado | Se retira del flujo habitual sin perder su historial. |

## Cambiar el estado

1. Abrí **Proyectos** y elegí el proyecto.
2. Entrá a **Configuración y equipo**.
3. Seleccioná el estado adecuado.
4. Guardá los cambios e informá al equipo si el estado modifica su forma de
   trabajo.

El estado no borra casos, ejecuciones ni evidencias. Antes de cerrar o archivar
un proyecto, verificá que la información necesaria esté guardada y que no haya
ejecuciones activas que el equipo deba finalizar.

## Ayuda rápida

- Usá **Bloqueado** para hacer visible un impedimento operativo, no para
  reemplazar el seguimiento de un bug.
- Usá **Cerrado** cuando el trabajo terminó; usá **Archivado** cuando además
  querés retirarlo del flujo principal.
- Si un estado no te deja realizar una acción esperada, revisá también tus
  permisos de proyecto con un administrador.
